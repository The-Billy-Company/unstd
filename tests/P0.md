# P0 boundary assurance

These are executable product and assurance suites. Every rejection has a working
control, every dangerous input has a parent deadline, and expected results come
from an independent authority or an explicitly observed OS/peer history.

| Boundary | Executable evidence |
| --- | --- |
| [Installed artifacts](suites/assurance/planes/packaging/README.md) | Frozen external build inputs; offline wheel/sdist/wheel-from-sdist; complete archive payload, metadata, licenses and RECORD; unseeded consumers outside checkout; public-module probe inventory; absent-extra errors; installed strict typing with negative controls. Required-extra execution also installs and exercises each extra in its own consumer. |
| [TLS peers](suites/assurance/security/pentest/README.md) | Independent roots/intermediate/leaf certificates; actual bounded loopback handshakes and authenticated exchange; root isolation, chain, DNS/IP SAN, wildcard, validity, EKU, mTLS identity and combined PEM; default protocol rejection and named legacy acceptance. |
| [Filesystem failures](suites/product/fs/integration/README.md) | Commit-stage fault matrix and exact error identity; old/new contents and resource ownership; secondary cleanup failures; exclusive temp creation/collisions/symlinks; deterministic killed writers; reader/writer generations; directory durability ordering and platform-specific refusal. |
| [Process failures](suites/product/proc/integration/README.md) | Literal hostile argv; Unicode paths, explicit env/cwd/stdin; missing executables; concurrent large output; positive finite timeout validation before launch; partial output, direct-child kill/reap, signal exits, logging errors and recovery. |
| [Parser boundaries](suites/product/serde/security/test_parser_boundaries.py) | Strict Base64 alphabet/padding/junk against stdlib; JSON malformed input/encoding/strict ingress hooks; exact NDJSON line/error histories, callback and I/O failure identity, gzip truncation, writer prefix and consumption; deep input in isolated workers. |
| [Bearer authentication](suites/product/crypto/security/test_token_boundary.py) | Independent stdlib Base64 + raw BLAKE3 envelopes; byte mutations, all truncations, malformed separators, Unicode, invalid keys, signed noncanonical payloads, ignored junk and unused-bit aliases; opaque claims retain exact bytes. |
| [Regex execution](suites/product/rex/security/test_regex_boundary.py) | Native-operation observation, successful matching controls and long hostile subjects in killable workers; explicit fallback classification; stdlib syntax rejection and callback side-effect/error identity. |
| [YAML construction](suites/product/yaml/security/test_yaml_boundary.py) | Unknown/Python tags cannot execute fixture-owned constructor expressions; safe scalar controls; duplicate semantic keys, valid merges and stream ownership; shared and recursive aliases; bounded deep/malformed input with exact small controls and graph identity summaries. |

## Run required evidence

```console
uv sync --locked --all-extras --group dev
uv build --sdist --wheel --out-dir /tmp/unstd-build-cache
uv run --no-sync python -m tests.tooling check
uv run --no-sync pytest --require-extras -q
```

The ordinary dependency preparation/build populates uv's cache. Packaging tests
then build and install offline; they never repair missing cache entries by
fetching during pytest. Build prerequisites and required extra artifacts must be
available. Missing capabilities fail a required run with an actionable error.
The CI all-extra and dependency-floor jobs use this posture. The fallback job
does not request extras; TLS and the filesystem/process boundaries still run.

For focused execution:

```console
uv run --no-sync python -m tests.tooling run packaging -- --require-extras -q
uv run --no-sync python -m tests.tooling run pentest -- -q
uv run --no-sync python -m tests.tooling run integration -- -q
uv run --no-sync python -m tests.tooling run security-contracts -- --require-extras -q
```

## Changes pinned by the tests

- `proc.run` rejects missing, nonnumeric, boolean, nonpositive and nonfinite
  timeouts before spawning. A direct child is killed/reaped on expiry.
- Atomic writers retain descriptor ownership when stream construction fails.
  Rollback attempts all applicable cleanup and preserves the primary failure;
  secondary failures remain attached as exception notes. Directory syncing
  honors its documented best-effort behavior on unsupported platforms.
- Bearer verification requires canonical unpadded Base64url on both segments.
  Ignored junk, padding, alternate alphabets and unused-bit aliases cannot
  inherit an authentic MAC. General-purpose URL Base64 retains its documented
  lenient behavior. Non-ASCII MAC text returns false instead of raising.
- Editable YAML accepts the standard `!!str` tag as a supported string while
  preserving quote/anchor semantics and refusing unknown constructors.
- Native WAV one-shot and streaming writers select WAV explicitly for file-like,
  extensionless and misleading-extension destinations; independent `wave` reads
  verify the emitted headers and PCM.

## Scope and evidence limits

Fault schedules, certificate identities, raw inputs and expected histories are
reviewed test fixtures. Fixture processes/directories and loopback ports are
owned by the run. TLS uses one bounded deadline and unconditional peer cleanup.
Parser workers pin the checkout's source and return provenance; Linux adds CPU
and address-space limits, while every platform retains the parent wall deadline.
Alias summaries inspect graph identity without expanding the graph.

Process interruption demonstrates atomic visibility; power-loss durability needs
a controlled filesystem/VM experiment. Direct-child reaping does not promise
termination of arbitrary descendant trees. Named POSIX-only probes are guarded;
the suite does not claim a completed Windows/macOS CI matrix. Native regex
safety evidence applies to operations observed on the native backend; fallbacks
retain Python's backtracking behavior. Parser probes do not establish sanitizer
coverage inside third-party compiled code.

Coverage-guided mutation, full fuzz corpus lifecycle, sustained chaos, and stable
performance workers remain the separate work described in [COVERAGE.md](COVERAGE.md).
