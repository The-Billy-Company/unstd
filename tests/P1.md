# P1 product assurance

P1 broadens every public module beyond its P0 boundary. Each module has a
reviewed contract inventory in its suite README, generated laws or state
machines against an independent reference, and real-boundary evidence where
the contract has one. Every new file was shown to fail against a deliberately
broken source before it was accepted.

## Platform and dependency coverage

Linux keeps the full interpreter, floor and base-install matrix. The `platforms`
CI job runs the `api` and `contracts` groups with every extra on macOS and
Windows. The `extras` job installs each declared extra alone, plus text with
NumPy, and requires exactly the extras it installed through
`--require-extra NAME`. Every other backend is genuinely absent, so fallbacks
and missing-extra errors execute for real.

```console
uv sync --locked --extra text --group dev
uv run --no-sync python -m tests.tooling.ci run api -- --require-extra text -q
uv run --no-sync python -m tests.tooling.ci run contracts -- --require-extra text -q
```

Every partial combination and the base install have passed both groups on
macOS/CPython 3.13. Windows has not yet executed here; its first CI run must
name any POSIX-only probe it skips rather than skipping a module.

## Changes pinned by the tests

- `Codec.decode_or` returns the default for non-UTF-8 payload text instead of
  leaking msgspec's `UnicodeError`.
- `derive_key` rejects a non-`str` context; `None` previously produced the public
  digest of the key material.
- Portable array unpacking accepts only exact typestrs and measures every buffer
  in bytes, not `len()`.
- WAV fallbacks reject ragged frames and channel-count changes, and `write()`
  after `close()` raises the documented `ValueError`.
- `from_epoch_ms` keeps exact milliseconds far from the epoch.
- `windowed` defers its read-ahead until the first window is requested.
- NumPy `choices` rejects zero or negative weight totals like the stdlib engine.
- YAML merge chains no longer expand exponentially; editable output escapes NEL
  and never rewrites a parsed float to a different value.

## Divergences and open decisions

These are pinned as observed behavior or recorded without a behavior change:

- The TOML writer is tomlkit itself (`toml.dumps is tomlkit.dumps`). It spells
  ESC as the TOML 1.1 `\e`, which `tomllib` before 3.15 rejects, and silently
  writes invalid seconds-precision offsets and offset-aware times. The ESC case
  is a strict expected failure that flips when fixed.
- Soundfile reports, rather than raises, exceptions from caller streams, so
  exception-identity cases run on the stdlib fallbacks only.
- Upstream `SortedSet.add`/`update` and large `SortedList.update` merges are not
  failure-atomic under raising comparisons; the wrapper re-exports them verbatim.
- `digest.raw(None)` returns the empty-input digest (backend default).
- The gzipx native writer issues one sink write per `write()` call instead of
  stdlib buffering; decoded data is identical.
- ruamel departs from the YAML 1.2 core schema for `1_000`, `0b101`, `+0x1F` and
  `.5e3`, and rejects a tab after `key:`.
